# ACAS Xu BFS Reachability Idea

**Date:** 2026-04-17

---

## Motivation

The discrete compositional verification pipeline produces ~8,982 INVAR constraints
(1,659 SAT contracts × ~5.4 dangerous states per contract), causing nuXmv to segfault
during BDD construction. The root cause is that ~32% of discrete contracts are UNSAT —
meaning the NN genuinely selects the forbidden advisory at those exact integer states —
yet the monolithic nuXmv proof (`INVARSPEC: true`) confirms the closed-loop system is
safe. The only consistent explanation is that **UNSAT contract states are unreachable**
from any valid initial condition.

If we can compute the reachable state set directly, we can filter contract specs to
reachable states only before running CROWN. Expected outcomes:

- All surviving contracts verify SAT (no UNSAT, since unreachable states are removed)
- Far fewer INVAR constraints injected into the patched SMV
- nuXmv no longer segfaults

---

## The State Space

The closed-loop ACAS Xu model has the following discrete state variables:

| Variable | Domain | Size |
|---|---|---|
| `x_mag` | [0, 10] | 11 |
| `y_mag` | [0, 10] | 11 |
| `x_sign` | {−1, +1} | 2 |
| `y_sign` | {−1, +1} | 2 |
| `heading_own_var` | [0, 39] | 40 |
| `a_prev` (command) | 5 advisories | 5 |

**Total states: 11 × 11 × 2 × 2 × 40 × 5 = 96,800**

This is small enough for exhaustive BFS in milliseconds using Python — no nuXmv needed.

## BFS Algorithm

### Inputs

- Initial state set: read from `acas_template_360.tree` (or `acas_model_params.yaml`)
- Transition function: `simulate_step` from `generate_acas_contracts.py` (exact physics)
- NN advisory selection: ONNX forward pass for each of the 5 networks

### Pseudocode

```python
from collections import deque

reachable = set()
queue = deque(initial_states)  # tuples: (x_mag, y_mag, x_sign, y_sign, heading_own_var, a_prev)

while queue:
    state = queue.popleft()
    if state in reachable:
        continue
    reachable.add(state)

    x_mag, y_mag, x_sign, y_sign, heading_own_var, a_prev = state

    # Select NN based on a_prev
    nn = load_nn(a_prev)  # one of the 5 ONNX networks
    nn_inputs = normalize(x_mag, y_mag, x_sign, y_sign, heading_own_var)
    advisory = argmax(nn.forward(nn_inputs))  # deterministic

    # Apply advisory to get next physical state
    next_physical = simulate_step(x_mag, y_mag, x_sign, y_sign,
                                  heading_own_var, advisory)
    next_x_mag, next_y_mag, next_x_sign, next_y_sign, next_heading = next_physical
    next_state = (next_x_mag, next_y_mag, next_x_sign, next_y_sign,
                  next_heading, advisory)  # advisory becomes next a_prev

    if next_state not in reachable:
        queue.append(next_state)
```

### Key properties

- **Deterministic**: the NN always produces the same output for the same input, so each
  state has exactly one successor. The reachability graph is a directed graph with
  out-degree 1 — it degenerates into a set of simple paths and cycles.
- **Termination**: the state space is finite (96,800 states); BFS terminates in at most
  96,800 steps.
- **Completeness**: BFS from all valid initial states produces the exact reachable set
  under the closed-loop dynamics.

## Filtering Contracts

Once `reachable_states.json` is produced, filtering works as follows:

For each contract in `contract_specs_eps1e4.json`:
- The contract is defined by `(heading_own_var, x_sign, y_sign, forbidden_advisory, dangerous_xy)`
- `a_prev` determines which NN is active (and is stored in the contract as `forbidden_advisory`'s
  corresponding NN index)
- For each `(x_mag, y_mag)` in `dangerous_xy`, check if
  `(x_mag, y_mag, x_sign, y_sign, heading_own_var, a_prev)` ∈ reachable set
- Keep only the dangerous states that appear in the reachable set
- If no dangerous states survive, drop the contract entirely

### Expected outcome

If the unreachability proof holds (which follows from the monolithic nuXmv `INVARSPEC: true`),
**all dangerous states in every UNSAT contract are unreachable**, and the filtered contract set
should have:

- 0 UNSAT contracts (all surviving dangerous states verified SAT by CROWN)
- Fewer total dangerous states → fewer INVAR constraints → no nuXmv segfault
- A self-contained pipeline that does not require the monolithic nuXmv run at all

## Implementation Plan

### New script: `generate_reachable_states.py`

```
AcasXu_closed_loop/
└── generate_reachable_states.py      # BFS; outputs reachable_states.json
```

**Inputs:**
- `networks/aprev_*.onnx` — the 5 ONNX networks
- Initial conditions from `acas_template_360.tree` or hardcoded from model params

**Output:**
- `reachable_states.json` — set of reachable `(x_mag, y_mag, x_sign, y_sign, heading_own_var, a_prev)` tuples

### Modified script: `generate_acas_contracts.py`

Add optional `--filter reachable_states.json` argument:
- When provided, drops dangerous states not in the reachable set
- Drops contracts with no remaining dangerous states
- Outputs filtered specs to a new file (e.g. `contract_specs_reachable.json`)

### Verification run

```bash
python3 generate_reachable_states.py \
    --output reachable_states.json

python3 generate_acas_contracts.py \
    --filter reachable_states.json \
    --output contracts/reachable_goals/contract_specs_reachable.json

python3 verify_acas_contracts.py \
    --spec contracts/reachable_goals/contract_specs_reachable.json \
    --discrete \
    --output contracts/reachable_goals/aprev_clear_crown_results.json

# ... repeat for all 5 NNs, then run compositional pipeline
```

## Open Questions

1. **What are the exact initial conditions?** The BFS seed states must match
   `acas_template_360.tree` exactly. Need to audit the template for the initial
   value assignments of all 6 state variables.

2. **Does filtering eliminate all UNSAT contracts?** This is expected from the
   unreachability proof, but should be verified empirically after running BFS.

3. **How many INVAR constraints remain?** The nuXmv segfault threshold is somewhere
   between ~1,659 (continuous, which works) and ~8,982 (discrete, which crashes).
   If filtered discrete contracts produce fewer than ~2,000–3,000 INVARs, the
   compositional pipeline should succeed.

4. **Does the compositional verdict become `INVARSPEC: true`?** If all filtered
   contracts are SAT and the INVAR constraints cover all reachable dangerous states,
   the compositional proof should close — without ever running the 9.6 GB monolithic
   nuXmv run.

5. **Continuous contracts with reachability filter:** BFS gives exact integer
   reachability. For continuous contracts, the bounding box covers non-integer real
   points between grid cells. Filtering continuous contracts by BFS reachability is
   valid (if the integer dangerous states are unreachable, the contract is moot), but
   the claim is slightly softer than for discrete contracts.

The BFS step replaces the monolithic nuXmv run as the source of reachability
information — and does so in milliseconds rather than 49 seconds and 9.6 GB of RAM.
